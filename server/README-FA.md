# راهنمای نصب و کنترل Edge Gateway

این بسته پنل فارسی مدیریت همین Gateway است. منطق امضا، مسیریابی، پروکسی و WebSocket حفظ شده و با اجازهٔ شما مقدارهای ثابت عملیاتی قابل‌تنظیم شده‌اند. ساخت تونل VPN و کلاینت اندروید مرحلهٔ بعد است.

## ۱. نصب روی سرور

هدف نصب‌کننده: Ubuntu یا Debian دارای systemd، با Python حداقل 3.10. Ubuntu 22.04/24.04 و Debian 12 دارای این پیش‌نیاز هستند؛ آزمون نصب کامل باید روی سرور مقصد انجام شود. معماری‌های amd64 و arm64 پشتیبانی شده‌اند. دسترسی root و دسترسی اینترنت به مخزن بسته‌های سیستم و go.dev لازم است.

ZIP را روی سرور باز کنید و وارد پوشهٔ `edge-gateway` شوید:

```bash
sudo bash install.sh
```

نصب‌کننده این کارها را می‌کند:

1. نصب ابزارهای لازم از apt و دریافت نسخهٔ stable زبان Go از منبع رسمی با بررسی SHA256.
2. اجرای تست‌های Go و Python و ساخت فایل اجرایی.
3. ساخت کاربر محدود `edge-gateway` و نصب سرویس مستقل Gateway.
4. نصب پنل، تولید گذرواژهٔ تصادفی و کلید تصادفی HMAC.
5. ساخت گواهی خودامضای ۳۰روزه فقط برای آزمون اولیه.
6. اجرای پنل روی `127.0.0.1:9090`. Gateway تا تنظیم و اعمال از پنل متوقف می‌ماند.

نصب‌کننده روی `/opt/edge-gateway` موجود، متوقف می‌شود تا نصب فعال ناخواسته بازنویسی نشود. هیچ فایروال یا rule شبکه‌ای را تغییر نمی‌دهد. برای اتصال واقعی، پورت انتخابی Gateway را در فایروال سیستم و ارائه‌دهندهٔ سرور باز کنید؛ پورت پنل لازم نیست عمومی باشد.

## ۲. ورود به پنل

روی کامپیوتر خودتان این اتصال را باز نگه دارید:

```bash
ssh -L 9090:127.0.0.1:9090 USER@SERVER_IP
```

سپس در مرورگر همان کامپیوتر وارد شوید:

```text
http://127.0.0.1:9090
```

گذرواژهٔ اولیه روی سرور:

```bash
sudo cat /root/edge-panel-credentials.txt
```

در اندروید نیز می‌توانید با کلاینت SSH دارای Local Port Forwarding همین مسیر را استفاده کنید. برای دسترسی عمومی HTTPS پنل، راهنمای انتهای این فایل را ببینید. پس از تغییر گذرواژه، فایل گذرواژهٔ اولیه قدیمی می‌شود؛ آن فایل صرفاً خروجی نصب اولیه است.

## ۳. ترتیب تنظیم اولین اتصال

1. در «گواهی‌های TLS»، full chain و کلید خصوصی بدون گذرواژهٔ دامنهٔ واقعی را وارد کنید. انتخاب گواهی ابتدا فقط فرم را عوض می‌کند.
2. در «اتصال و مسیریابی»، آدرس شنود، فهرست سرورهای داخلی و مقصد جایگزین واقعی را وارد کنید. هر خط یک backend؛ مسیر و query آدرس قابل‌استفاده است.
3. در «امنیت و امضا»، برای اتصال کلاینت از کلید HMAC مطلع باشید. با «تولید کلید جدید» کلید تازه نمایش داده می‌شود و تا زدن اعمال فعال نیست؛ کلید فعلی نیز در پشتیبان محرمانه وجود دارد. گذرواژهٔ پنل با کلید HMAC متفاوت است.
4. «بررسی تنظیمات» را بزنید. این کار JSON، مقدارها، گواهی و دسترسی کاربر سرویس به فایل‌ها را بررسی می‌کند و برنامهٔ واقعی Go را با `--check-config` اجرا می‌کند.
5. در صورت نیاز بررسی TCP مقصدها را انجام دهید. این تست فقط دسترسی TCP است؛ درستی پروتکل backend یا پاسخ واقعی را تضمین نمی‌کند.
6. «ذخیره و اعمال» را بزنید. سرویس restart شده و فعال‌بودن process و دسترسی TLS محلی بررسی می‌شود.
7. در «نمای کلی»، اجرای خودکار را فعال کنید تا Gateway پس از reboot اجرا شود. پنل از نصب اولیه اجرای خودکار دارد.

پورت 443 برای کاربر محدود سرویس با `CAP_NET_BIND_SERVICE` قابل‌استفاده است. پنل حداکثر `EDGE_SHUTDOWN_TIMEOUT=300s` را می‌پذیرد؛ سرویس systemd مهلت 310 ثانیه دارد.

## ۴. تنظیمات قابل‌کنترل

| کلید | پیش‌فرض اصلی / اولیه | کاربرد |
|---|---|---|
| `EDGE_ADDR` | `:8443` | آدرس و پورت HTTPS |
| `EDGE_INTERNAL_BACKENDS` | دو مقصد محلی نمونه | فهرست و ترتیب backendها |
| `EDGE_DECOY_ORIGIN` | در نصب خالی؛ باید تنظیم شود | مقصد درخواست فاقد امضای معتبر |
| `EDGE_ALLOW_INSECURE_DECOY` | `false` | HTTP جایگزین، فقط برای آزمون |
| `EDGE_HMAC_SECRET` | تولید تصادفی هنگام نصب | کلید مشترک با کلاینت |
| `EDGE_SIGNATURE_MAX_SKEW` | `5m` | بازهٔ زمانی اعتبار امضا |
| `EDGE_CERT_FILE` | گواهی مدیریت‌شده | مسیر گواهی ورودی |
| `EDGE_KEY_FILE` | کلید مدیریت‌شده | مسیر کلید خصوصی |
| `EDGE_TLS_MIN_VERSION` | `1.2` | حداقل TLS ورودی و خروجی |
| `EDGE_SHUTDOWN_TIMEOUT` | `30s` | مهلت خاموش‌شدن |
| `EDGE_READ_HEADER_TIMEOUT` | `10s` | زمان خواندن هدر |
| `EDGE_SERVER_IDLE_TIMEOUT` | `120s` | بیکاری اتصال ورودی |
| `EDGE_MAX_HEADER_BYTES` | `65536` | مقدار MaxHeaderBytes در Go |
| `EDGE_MAX_IDLE_CONNS` | `256` | کل اتصال‌های بیکار هر transport |
| `EDGE_MAX_IDLE_CONNS_PER_HOST` | `64` | اتصال بیکار هر میزبان |
| `EDGE_UPSTREAM_IDLE_TIMEOUT` | `90s` | بیکاری اتصال خروجی |
| `EDGE_TLS_HANDSHAKE_TIMEOUT` | `10s` | مهلت TLS خروجی |
| `EDGE_EXPECT_CONTINUE_TIMEOUT` | `1s` | مهلت Expect Continue |

عدد MaxHeaderBytes همان تنظیم Go است؛ parser ممکن است سربار داخلی داشته باشد، بنابراین به معنای سقف دقیق تمام بایت‌های روی سیم نیست. محدودیت‌های idle نیز تعداد کاربران فعال یا سقف حجم مصرفی نیستند.

## ۵. اعمال و بازیابی

- هر اعمال با revision بررسی می‌شود؛ فرم قدیمی در تب دوم نمی‌تواند تنظیمات جدید را بی‌خبر بازنویسی کند.
- قبل از نوشتن، اعتبارسنجی انجام می‌شود. فایل env با فایل موقت، fsync و rename اتمیک ذخیره می‌شود.
- تنظیمات قبلی در تاریخچه ثبت می‌شوند و وضعیت قبل از تغییر در journal تراکنش ذخیره می‌شود.
- اگر سرویس جدید بالا نیاید، تنظیمات و وضعیت قبلی برمی‌گردند. اگر خود بازیابی سرویس شکست بخورد، خطا صریح نمایش داده می‌شود و journal باقی می‌ماند.
- اگر پنل وسط عملیات متوقف شود، در شروع بعدی journal بررسی و وضعیت قبلی بازیابی می‌شود.
- گواهی‌های واردشده فایل جدید با نام تصادفی می‌گیرند؛ جفت گواهیِ در حال استفاده درجا بازنویسی نمی‌شود.
- اعمال تنظیمات و restart ممکن است اتصال فعال را قطع کند. هستهٔ اصلی WebSocket ارتقایافته را در graceful shutdown مدیریت نمی‌کند؛ این رفتار دستکاری نشده است.
- بررسی آمادگی محلی به معنی تأیید سلامت همهٔ backendها، DNS بیرونی، firewall یا اتصال از ایران نیست.

تاریخچه تا ۵۰ نسخه حفظ می‌شود. گواهی‌های قدیمی خودکار حذف نمی‌شوند، چون ممکن است نسخه‌های پشتیبان به آن‌ها نیاز داشته باشند. پشتیبان JSON شامل تنظیمات، HMAC و جفت گواهی است؛ شامل گذرواژهٔ مدیر، فایل اجرایی، لاگ‌ها و تنظیمات systemd نیست. واردکردن فایل پشتیبان ابتدا فرم را پر می‌کند و برای فعال‌شدن به «ذخیره و اعمال» نیاز دارد.

## ۶. مسیرها و فرمان‌های عملیاتی

```text
/opt/edge-gateway/                     کد و فایل اجرایی
/opt/edge-gateway/original/main.go     نسخهٔ اصلی بدون تغییر بایت
/etc/edge-gateway/edge-gateway.env     تنظیمات Gateway
/etc/edge-gateway/certs/               جفت گواهی‌ها
/var/lib/edge-panel/auth.json          هش گذرواژهٔ مدیر
/var/lib/edge-panel/revisions/         نسخه‌های قبلی تنظیمات
/var/lib/edge-panel/transaction.json   تراکنش در حال انجام/بازیابی
/var/lib/edge-panel/audit.jsonl        رخدادهای مدیریت
/opt/edge-go/                         Go دریافت‌شده برای ساخت
```

```bash
sudo systemctl status edge-panel edge-gateway
sudo journalctl -u edge-panel -n 100 --no-pager
sudo journalctl -u edge-gateway -n 100 --no-pager
```

بازنشانی گذرواژه:

```bash
sudo python3 /opt/edge-gateway/panel/server.py --init-password
sudo systemctl restart edge-panel
```

خاموش‌شدن پنل Gateway را متوقف نمی‌کند. خاموش‌کردن Gateway از پنل یا systemd، خود Gateway را متوقف می‌کند.

### ساخت مستقیم با Go

```bash
go test ./...
go build -buildvcs=false -trimpath -o edge-gateway .
```

از `go run .` استفاده کنید؛ `go run main.go` فایل `tuning.go` را وارد build نمی‌کند. تنظیمات محیطی مانند نسخهٔ اصلی لازم‌اند. برای پیش‌بررسی، فایل اجرایی `--check-config` را می‌پذیرد. این حالت اعتبارسنجی است و listener باز نمی‌کند.

### انتقال تنظیمات قدیمی

قبل از نصب، env و گواهی‌های قبلی را نگه دارید. نصب فعال موجود خودکار جایگزین نمی‌شود. پس از نصب جدید، مقدارها را در فرم‌ها وارد و گواهی‌ها را از بخش TLS وارد کنید. پنل فقط مسیرهای `/etc/edge-gateway/certs/` را برای گواهی می‌پذیرد؛ این محدودیت پنل است، قابلیت اصلی Go برای مسیر دلخواه همچنان وجود دارد.

### انتشار در GitHub

محتوای همین پوشه را در ریشهٔ repository خود قرار دهید. فایل `.gitignore` از افزودن فایل‌های رایج حاوی کلید جلوگیری می‌کند؛ هیچ secret واقعی در این بسته نیست. ZIP تولیدشده هنوز در GitHub منتشر نشده است.

```bash
git clone https://github.com/YOUR_ACCOUNT/YOUR_REPO.git
cd YOUR_REPO
git checkout YOUR_TAG_OR_COMMIT
sudo bash install.sh
```

یا از فایل `bootstrap.sh` با آدرس GitHub HTTPS و tag/commit بررسی‌شده استفاده کنید. Actions شامل تست‌ها و یک آزمون اختیاری نصب روی runner اوبونتو است. اجرای دستی workflow آزمون نصب را نیز اجرا می‌کند.

### به‌روزرسانی کد

این نسخه دکمهٔ دریافت و اجرای کد جدید از اینترنت ندارد. نصب‌کننده نصب موجود را بازنویسی نمی‌کند. برای ارتقا روی سرور واقعی، ابتدا پشتیبان پنل و کپی `/opt/edge-gateway` را بگیرید، کد جدید را در مسیر جداگانه تست و build کنید، `edge-panel` و سپس `edge-gateway` را متوقف کنید، فایل‌های اجرایی/منبع را با نسخهٔ آزموده عوض کنید و سرویس‌ها را راه‌اندازی کنید. پوشه‌های `/etc/edge-gateway` و `/var/lib/edge-panel` نباید بازنویسی شوند. تغییر unit نیاز به `systemctl daemon-reload` دارد. برای فایل اجرایی mode `0750` و مالکیت `root:edge-gateway` را حفظ کنید. ارتقای بدون قطعی در این نسخه ارائه نشده است.

### دسترسی عمومی HTTPS به پنل (اختیاری)

پیش‌فرض توصیه‌شده همان SSH tunnel است. اگر دامنهٔ مدیریتی و گواهی معتبر آماده دارید، یک drop-in با `sudo systemctl edit edge-panel` بسازید؛ نام‌ها و مسیرها را با مقادیر واقعی خود جایگزین کنید:

```ini
[Service]
ExecStart=
ExecStart=/usr/bin/python3 /opt/edge-gateway/panel/server.py --host 0.0.0.0 --port 9090 --public-host panel.example.com:9090 --tls-cert /etc/edge-gateway/certs/panel.crt --tls-key /etc/edge-gateway/certs/panel.key
```

سپس daemon-reload و restart کنید. نشانی مرورگر دقیقاً `https://panel.example.com:9090` است و گواهی باید آن دامنه را پوشش دهد. CLI از bind عمومی بدون TLS و public-host جلوگیری می‌کند. reverse proxy برای پنل در این نسخه پیکربندی نشده است؛ ارتباط مستقیم HTTPS یا SSH را استفاده کنید. پنل برای کنترل سرویس و فایل‌ها root اجرا می‌شود و به مدیر مورداعتماد اختصاص دارد؛ برای دسترسی عمومی، محدودکردن IP مدیریتی در فایروال مناسب است. دسترسی عمومی پنل و تمدید گواهی نیاز به آزمون روی همان سرور دارد.

## ۷. محدودیت‌ها و مرز این تحویل

- همهٔ ۱۸ تنظیم تعریف‌شده برای Gateway کنترل می‌شوند؛ ویرایش آزاد الگوریتم و کد از داخل مرورگر وجود ندارد.
- سیاست HMAC، نبود امضای بدنه، نبود cache ضد replay و روش round-robin همان نسخهٔ اصلی است.
- API WebSocket مرورگر نمی‌تواند هدر امضای دلخواه بگذارد؛ کلاینت اندروید باید قرارداد فعلی را پیاده‌سازی کند.
- این مرحله VPN کامل، حساب کاربران VPN، سهمیهٔ ترافیک، تونل TUN، ساخت اشتراک یا اپ اندروید اضافه نمی‌کند.
- تمدید خودکار گواهی، تغییر فایروال، تعویض سیستم‌عامل و تنظیم همهٔ directiveهای systemd از UI انجام نمی‌شود.
- تضمین صفر خطا یا صفر تغییر بایت در همهٔ شرایط شبکه ممکن نیست. پروکسی استاندارد هدرهای hop-by-hop را طبق رفتار اصلی مدیریت می‌کند؛ آزمون‌های مشخص در گزارش ثبت شده‌اند.
- نصب کامل روی سرور واقعی کاربر هنوز انجام نشده؛ نتیجهٔ آزمون محیط توسعه جای آن را نمی‌گیرد.
